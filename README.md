A [Morphe](https://morphe.software) patch source with exactly one patch, **Allow Gearslip**. It lets
Waze accept [Gearslip](https://github.com/Seb3thehacker/gearslip), the open-source Android Auto
alternative, as a host for its car screen.

## Why Waze refuses Gearslip

Waze's car screen is built on the AndroidX Car App Library. Before a host may draw the car screen,
the library's `HostValidator` checks whether that host is allowed.

- Up to Car App Library 1.8.0-beta01, any host that holds `android.car.permission.TEMPLATE_RENDERER`
  passes this check. Gearslip holds that permission.
- Since 1.8.0-rc01 and 1.9.0-alpha02, the permission counts only on Android Automotive. On a phone,
  only hosts on the app's own allowlist pass, and Waze's allowlist names only Android Auto.

Gearslip therefore gets no binder back and reports `the app refused to bind - host not accepted`.

## What the patch does

1. It finds `HostValidator.validateHost(HostInfo)` in Waze. R8 renames this method, so the patch
   looks for the strings it leaves behind ("doesn't match caller's actual UID", "Unrecognized
   host"). If those are gone, it falls back to looking for the permission string and the
   `Process.myUid()` check. If it cannot find exactly one matching method, it stops with an error
   and changes nothing.
2. At the start of that method it calls `CarHosts.allowed(hostInfo, allowlist)`, from the small
   extension this patch bundles. A host on the patch's list is accepted only if all three match:
   - the package name,
   - the UID,
   - the SHA-256 of the signing certificate.
3. Every other host goes through Waze's own check, unchanged. Android Auto keeps working as before,
   and no other app gains access.

### Option: Accepted hosts

Entries have the form `digest,package` and are separated by `;`. The digest is the SHA-256 of the
host's signing certificate (64 lowercase hex characters, as printed by
`apksigner verify --print-certs`), or `*` for any certificate.

| Preset | Value |
| --- | --- |
| Gearslip release builds (default) | `4cc56ebdd13a54d260eca9b7e2b2ae6b30e2f225bfda8f508f0709edf084948b,app.seb3thehacker.gearslip` |
| Gearslip, any build (also self-built) | `*,app.seb3thehacker.gearslip` |

The default digest is the one Gearslip publishes in its
[docs/BUILDING_APPS.md](https://github.com/Seb3thehacker/gearslip/blob/main/docs/BUILDING_APPS.md).

## Usage

1. Add this patch source to Morphe Manager in one of two ways:
   - **Link:** [Add waze-gearslip-patch to Morphe Manager](https://morphe.software/add-source?github=VoltoxderEchte/waze-gearslip-morphe-patch).
   - **Local file:** download `waze-gearslip-patch-1.0.0.mpp` from the
     [latest release](https://github.com/VoltoxderEchte/waze-gearslip-morphe-patch/releases/latest)
     and add it as a local source.
2. Pick Waze and apply **Allow Gearslip**. The patch targets Waze **5.24.5.0** (APKM). Other
   versions are marked experimental, because the patch doesn't depend on renamed class names.

Known limitations:

- Gearslip still shows Waze with a red X in its launcher. The X is only a badge, and you can still
  tap the tile. Gearslip also won't start Waze automatically as the navigation app.
- Once Waze accepts the host, it may still need something Gearslip doesn't offer, such as
  Google-specific host services. For debugging, check logcat under the `CarApp.Val` tag and in
  Gearslip's own log.

## Building

You need:

- JDK 17 or newer.
- An Android SDK with platform 36 and build-tools 36. Set `sdk.dir` in `local.properties`.
- `morphe-patches-gradle-plugin` 1.3.4 and `morphe-patcher` 1.13.0. Morphe publishes these to
  GitHub Packages, which needs a GitHub token. Without one, build them from source:
  1. Clone
     [morphe-patches-gradle-plugin](https://github.com/MorpheApp/morphe-patches-gradle-plugin)
     at tag `v1.3.4` and [morphe-patcher](https://github.com/MorpheApp/morphe-patcher) at tag
     `v1.13.0`.
  2. In each `build.gradle.kts`, remove the `signing` block and the GitHub Packages repository.
  3. Run `./gradlew publishToMavenLocal` in each. For the patcher, add `-x test -x apiCheck`.
     `settings.gradle.kts` looks in `mavenLocal()` first.

Then build the bundle:

```bash
./gradlew :patches:buildAndroid generatePatchesList -Pgpr.user=local -Pgpr.key=none
```

The bundle lands in `patches/build/libs/patches-<version>.mpp`. The plugin requires `gpr.user` and
`gpr.key` to be set, so the command passes placeholders. With a real token they also let Gradle
fetch the plugin from GitHub Packages.

On Windows, Java may fail with `Unable to establish loopback connection` when the temp path is
long. To fix it, set `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:\gjt`.
